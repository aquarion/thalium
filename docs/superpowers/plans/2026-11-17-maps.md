# Maps tab and Maps page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Images and PDFs under `Maps` directories leave Art/Documents and appear in a per-system Maps tab and a root Maps page, which also covers the `RPG/Maps` tree beside `Systems`.

**Architecture:** Maps are a new `map` kind in `media_items`. A pure `MediaClassifier` decides, from a source (`library` or `maps` disk) and a relative path, whether a file is a map and what its system, collection and tags are. `MediaIngestService`, `LibrisService::scanFile()` and `libris:update_media` use it, so map PDFs go to `media_items` instead of Elasticsearch. System-agnostic maps have no system; a system's Maps tab matches them to it by collection name at query time.

**Tech Stack:** Laravel 13, PHP 8.4, PHPUnit, Imagick, Elasticsearch (untouched except skipping/deleting map PDFs), Ansible/nginx in `autopelago`.

**Spec:** `docs/superpowers/specs/2026-11-17-maps-design.md`

## Global Constraints

- A directory segment equal to `Maps`, case-insensitive, **below the system directory** (path index ≥ 1, never the filename) marks a Systems-library file as a map. The `Maps` segment is dropped from `tags`; a system directory itself named `Maps` is not a map folder.
- `RPG/Maps` tree: every jpg/jpeg/png/webp/gif/pdf is a map, except files directly in the root and anything under a dot file/directory. First directory = `collection` (normalised: `-`/`_` become spaces); `system` is null; `tags` = directories below it.
- Outside Maps locations nothing changes: images are Art, PDFs are Documents.
- Ignored types: psd, psb, tif, bmp, zip, db, lnk, sh, txt.
- Map PDFs are never indexed in Elasticsearch, and any existing Elasticsearch document for one is deleted.
- Existing `libris` disk root, `/_libris/` URLs and Elasticsearch paths are unchanged. Library `path_hash` stays `sha1($path)`; maps-source rows use `sha1("maps\0".$path)` (plan call: no backfill needed, same uniqueness effect).
- Maps disk: `maps`, root `env('MAPS_LIBRARY')`, URL `APP_URL.'/_maps'`. If `MAPS_LIBRARY` is unset, the maps source is silently skipped everywhere.
- Prune keeps its "root has no directories, skip" guard, per source.
- Code style: methods end with `}// end name()`, as in the surrounding files.

## Review Focus

- Case/depth: `S/maps/a.png`, `S/Dungeons/MAPS/Deep/a.pdf` are maps; a system literally named `Maps` (`Maps/a.png`) and a file named `Maps.pdf` are not.
- Same relative path in both sources must not collide as one `media_items` row.
- Unset or empty `MAPS_LIBRARY` must not break `libris:update_media` or wipe library rows on prune.
- Existing Art rows under a `Maps` folder (mtime unchanged) must be reclassified on the next update.
- A map PDF already in Elasticsearch must vanish from Documents counts after its next scan.
